### Fixed

- **`@reticlehq/core`, `@reticlehq/engine`: `element` predicates rejected the flat `scope` and `self` fields that the syntax and `look find` both accept.** A step written as `{kind: "element", text: "...", scope: "#panel"}` failed to compile, and the only accepted spelling was the nested `query` form — so the shorthand worked everywhere except the place it was documented for. The engine also carried a second, drifting copy of the field table. `scope` and `self` are now lifted into the query like every other shorthand, and the engine derives the table from core instead of keeping its own. Closes [#1375](https://github.com/reticlehq/reticle/issues/1375).

- **`@reticlehq/engine`: an `element` predicate carrying a `source` stamp next to a `by`+`value` locator — or next to `self: true` — could pass for an element other than the one the caller's source location named.** `source` is an anchor, read by the browser on exactly the two branches `component` is: `by: "component"`, and the auto-anchor path taken when there is no `by`+`value`. On any other `by`+`value` the locator resolves by that pair and returns before the source stamp is ever consulted, and `self: true` returns the scope root and nothing else — but the engine claimed `source` as a used field everywhere, so the predicate reported a match it had not actually anchored. `source` is now claimed on the branches that read it and refused on the ones that don't, exactly as `component` already was — the caller gets a refusal naming the field instead of a verdict for the wrong element.
